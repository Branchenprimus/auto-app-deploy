Platform Overview

A fully automated GitOps pipeline that builds, ships, and secures web applications on a Raspberry Pi k3s cluster — driven entirely by Git tags.

⚙️ GitOps Source of Truth

All desired state lives in apps/*.yaml. No manual cluster commands needed.

Each app is described by a single YAML file in apps/. Pushing a new tag is the only manual action a developer needs to take — the rest of the pipeline is fully automated.

ArgoCD Helm GitHub Actions
🐳 Container Registry

Images are built for linux/arm64 and pushed to GitHub Container Registry (GHCR).

The GitHub Actions release workflow uses Docker Buildx + QEMU to cross-compile images for the Raspberry Pi's ARM64 architecture and pushes them to ghcr.io/branchenprimus/<app>:vX.Y.Z.

GHCR linux/arm64 Buildx + QEMU
☸️ k3s on Raspberry Pi

Lightweight Kubernetes with Traefik ingress. All apps run in the apps namespace.

k3s runs on a single Raspberry Pi with Traefik as the bundled ingress controller. ArgoCD manages all workloads using a shared Helm chart that provisions a Deployment, Service, Ingress, and optionally a PersistentVolumeClaim per app.

k3s Traefik ArgoCD
☁️ Cloudflare Tunnel + Zero Trust

A wildcard tunnel exposes all *.darwin-labs.org apps behind Cloudflare Access.

Traffic flows: Browser → Cloudflare Tunnel → Cloudflare Access (Google login) → Traefik → Kubernetes pod.

Cloudflare Access policies are managed by Terraform (HCP Terraform Cloud) and automatically applied whenever apps/*.yaml changes on main.

Cloudflare Tunnel Zero Trust Terraform Google IdP
🏠 Homepage Discovery

Apps appear on the internal dashboard automatically via Ingress annotations — no manual config.

The shared Helm chart injects Homepage annotations into every Ingress resource. After ArgoCD syncs a new app, Homepage discovers it automatically from the Kubernetes API. Custom labels, descriptions, and icons can be set in app.yaml.

Auto-discovery Ingress annotations
🔐 Secret Management

All tokens are stored in KeePassXC and injected at runtime via shell scripts or GitHub Secrets.

The scripts/setup-gitops-token-store.sh script bootstraps a KeePassXC database at ~/.config/auto-app-deploy/secrets.kdbx. Individual tokens are then read by automation scripts and stored as GitHub repository secrets.

KeePassXC GitHub Secrets

Deployment Flow

Click any step to expand details. A release is triggered by pushing a Git tag — everything else is automated.

1. Developer pushes a release tag
▼
The developer runs git tag v0.1.0 && git push origin v0.1.0 (or uses scripts/create-release.sh which automates tagging, watches Actions, and polls ArgoCD / kubectl for rollout status).

The tag push triggers the app repo's GitHub Actions release workflow.
2. GitHub Actions — Build & Push image to GHCR
▼
The release workflow (app-template/.github/workflows/release.yaml) runs on ubuntu-latest:

• Reads app.yaml for the image repository name.
• Logs into GHCR using the built-in GITHUB_TOKEN.
• Sets up QEMU + Docker Buildx for cross-compilation.
• Builds and pushes ghcr.io/branchenprimus/<app>:vX.Y.Z for linux/arm64.
3. GitHub Actions — Update GitOps repo
▼
Same workflow checks out Branchenprimus/auto-app-deploy using GITOPS_TOKEN and:

• Copies app.yaml into apps/<name>.yaml.
• Sets image.tag to the new version tag.
• Sets namespace: apps and image.pullPolicy: IfNotPresent.
• Commits and pushes to main with message "Deploy <app> vX.Y.Z".
4. ArgoCD detects change & syncs
▼
ArgoCD watches the main branch of auto-app-deploy. Its ApplicationSet generator scans apps/*.yaml and creates or updates one ArgoCD Application per file.

With automated: prune: true, selfHeal: true, ArgoCD immediately applies any diff between the desired state in Git and the live cluster state — no manual sync needed.
5. Helm renders Kubernetes resources
▼
ArgoCD renders chart/single-container-webapp using the app's apps/*.yaml as Helm values. This produces:

• Deployment — pulls the new image tag, sets env vars, resource limits.
• Service — ClusterIP service pointing to the container port.
• Ingress — Traefik ingress with Homepage annotations and the app hostname.
• PersistentVolumeClaim (optional) — only if persistence.enabled: true.
6. Cloudflare Access workflow triggers
▼
A separate GitHub Actions workflow (.github/workflows/cloudflare-access.yaml) fires whenever apps/*.yaml changes on main.

It copies the YAML files into terraform/cloudflare-access/apps/ and runs terraform apply via HCP Terraform Cloud using TF_API_TOKEN and CLOUDFLARE_API_TOKEN. This creates or updates Cloudflare Access Applications for each app that has access.enabled: true.
7. Traffic routing to the running pod
▼
User traffic follows this path:

Browser → Cloudflare Tunnel (wildcard *.darwin-labs.org → localhost:80) → Cloudflare Access (Google login check) → Traefik (routes by hostname) → Kubernetes Service → App pod.

The GHCR pull secret (ghcr-pull) is used by the pod to pull the private image.

Platform Components

The platform is assembled from these individual pieces, each with a single responsibility.

📁apps/*.yaml

One file per app. The single source of truth for desired deployment state.

Each file is copied from the app repo's app.yaml by the release workflow, with image.tag updated to the new release. Contains image repository, container port, route hostname, resource requests/limits, optional persistence, and Cloudflare Access flag. 
name: my-app
image:
  repository: ghcr.io/branchenprimus/my-app
  tag: v0.2.0
container:
  port: 80
route:
  host: my-app.darwin-labs.org
access:
  enabled: true
⎈ArgoCD ApplicationSet

Dynamically generates one ArgoCD Application per apps/*.yaml file.

Uses the Git files generator to watch apps/*.yaml. Each generated Application points to the shared Helm chart at chart/single-container-webapp and uses the matching apps/*.yaml as its Helm values file. Auto-sync with prune and self-heal means the cluster always converges to Git state.
📦Helm Chart: single-container-webapp

Shared chart that renders all Kubernetes resources for any single-container web app.

Templates: deployment.yaml, service.yaml, ingress.yaml, pvc.yaml.

The ingress template injects Homepage annotations automatically so the app dashboard discovers new apps without additional config. PVC is only rendered when persistence.enabled: true.
🔄Release Workflow

GitHub Actions workflow triggered by v* tags. Builds image, updates GitOps.

Runs on ubuntu-latest. Steps:
1. Checkout app repo.
2. Read name and image.repository from app.yaml via yq.
3. Login to GHCR with GITHUB_TOKEN.
4. Build & push ARM64 image.
5. Checkout auto-app-deploy with GITOPS_TOKEN.
6. Update and commit apps/<name>.yaml.
🌐Cloudflare Tunnel

Single wildcard tunnel routes all *.darwin-labs.org traffic to Traefik on port 80.

Configured once on the platform level. The tunnel runs on the Pi and forwards all subdomains to localhost:80 (Traefik). Per-app hostnames are handled by Traefik's Ingress routing rules, so no tunnel changes are needed when adding new apps.
🔒Cloudflare Zero Trust Access

Per-app Access Applications enforce Google login before requests reach the cluster.

Managed by Terraform (HCP Terraform Cloud workspace cloudflare-access). The cloudflare-access.yaml GitHub Actions workflow syncs apps/*.yaml into Terraform and runs terraform apply automatically. Apps with access.enabled: false are publicly reachable.
🏠Homepage

Auto-discovers deployed apps from Kubernetes Ingress annotations. Protected by Cloudflare Access.

Deployed via kubectl apply -f platform/homepage.yaml. Accessible at https://homepage.darwin-labs.org. Discovery is fully automatic from Ingress annotations — no manual YAML entries needed. Custom name, description, and icon can be set in app.yaml under the homepage: key.
📜Automation Scripts

Shell scripts for bootstrapping the platform and creating new apps.

setup-gitops-token-store.sh — creates the KeePassXC database and stores the GitOps PAT.
create-new-app.sh — interactive wizard: creates/prepares app repo, writes app.yaml, copies release workflow, sets issue labels and GitHub secret.
create-release.sh — tags, pushes, watches Actions + ArgoCD rollout.
setup-ghcr-pull-secret.sh — creates the ghcr-pull Kubernetes secret.

Secrets & Tokens

Every secret has a specific scope. None are committed to Git.

KeePassXC at ~/.config/auto-app-deploy/secrets.kdbx is the local master store. Scripts read tokens from it at runtime. GitHub repository secrets carry tokens into CI.
Token Used by Permissions required Stored in
GITOPS_TOKEN App repo GitHub Actions; create-new-app.sh Contents: Write on auto-app-deploy KeePassXC + GitHub repo secret per app
GITHUB_TOKEN App repo GitHub Actions (built-in) packages:write to push to GHCR Automatically injected by GitHub Actions
GHCR pull token Kubernetes cluster (ghcr-pull imagePullSecret) read:packages (classic PAT) Kubernetes secret via setup-ghcr-pull-secret.sh
TF_API_TOKEN Cloudflare Access GitHub Actions HCP Terraform workspace access GitHub Actions secret on auto-app-deploy
CLOUDFLARE_API_TOKEN HCP Terraform Cloud Cloudflare Access: edit HCP Terraform workspace variable
Google OAuth client HCP Terraform Cloud (optional) Google Cloud OAuth client credentials HCP Terraform workspace variable

Onboarding a New App

Two paths: fully automated via script, or step-by-step manually.

Prerequisites
Tools needed: gh (GitHub CLI), keepassxc-cli, git, docker.
One-time setup: run scripts/setup-gitops-token-store.sh to store the GitOps PAT in KeePassXC.
Automated (recommended)
Run create-new-app.sh
▼
The script prompts for local app path, GitHub owner/repo, app name, hostname, port, and whether Cloudflare Access should be enabled. It then creates/prepares the GitHub repo, writes app.yaml, copies the release workflow, sets issue labels, and stores GITOPS_TOKEN as a GitHub secret.
Add a Dockerfile to your app
▼
The container must run an HTTP server on a known port and the image must build for linux/arm64. Test locally:
docker build -t my-app:local .
docker run --rm -p 8080:<port> my-app:local
curl -I http://localhost:8080
Push a version tag
▼ 
git tag v0.1.0
git push origin v0.1.0
GitHub Actions builds the image, updates the GitOps repo, ArgoCD syncs the cluster, and Terraform updates Cloudflare Access — all automatically.
